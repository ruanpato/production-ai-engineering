# Capítulo 5.3 — Tracing semântico

## 🎯 Objetivo

Definir, em nível operacional, o **conteúdo mínimo de um trace** em sistemas de IA. Sem padronização, traces ficam ilegíveis e a investigação de incidente vira garimpo.

## 🧠 Tipos de span

| Tipo | Atributos chave |
|---|---|
| **LLM call** | `model.name`, `model.version`, `prompt.version`, input/output tokens, cost, latency, ttft |
| **Embedding** | `model.name`, `dimensions`, batch_size, latency |
| **Tool call** | `tool.name`, `tool.version`, args (redigido), result_size, error |
| **Retrieval** | `index`, `dimensions`, `top_k`, filters, scores |
| **Agent execution** | `agent.name`, `agent.version`, total tokens, steps, decision_path |
| **Handoff (multi-agent / A2A)** | `from`, `to`, `task_id`, payload size |
| **Human approval** | requester, approver, decision, latency |
| **Policy decision** | `policy.bundle`, decision, reason |
| **ML inference** | `model.name`, `model.version`, features hashing, latency, output |

## 🧭 Correspondência com OpenTelemetry GenAI

Os nomes acima são os do livro. O OpenTelemetry mantém convenções semânticas para GenAI (`gen_ai.*`) que cobrem o mesmo terreno; a correspondência, para quem exporta via OTel:

| Campo do livro | Atributo `gen_ai.*` | Observação |
|---|---|---|
| `model.name` | `gen_ai.request.model` (pedido) / `gen_ai.response.model` (resposta) | O modelo efetivamente servido pode diferir do pedido |
| provedor | `gen_ai.provider.name` | Substituiu `gen_ai.system` em agosto de 2025 (v1.37.0) |
| input/output tokens | `gen_ai.usage.input_tokens` / `gen_ai.usage.output_tokens` | Há atributos específicos para tokens de cache, áudio, imagem e raciocínio |
| operação (chat, embeddings, retrieval) | `gen_ai.operation.name` | Obrigatório; dá nome ao span (`{operação} {modelo}`) |
| agente (`agent.name`, steps) | spans `invoke_agent` / `create_agent` com `gen_ai.agent.name`; `execute_tool` com `gen_ai.tool.name` e `gen_ai.tool.call.id` | `invoke_agent` é CLIENT para agente remoto e INTERNAL para agente in-process |
| conversa / sessão | `gen_ai.conversation.id` | Correlaciona turnos de uma mesma conversa |
| conteúdo de prompt e resposta | `gen_ai.input.messages` / `gen_ai.output.messages` | **Opt-in**: não capturado por padrão, por privacidade; os eventos por mensagem antigos foram depreciados |
| tool call via MCP | `mcp.method.name`, `mcp.session.id`, `mcp.protocol.version`; tool calls com `gen_ai.operation.name=execute_tool` | Contexto de trace propagado em `params._meta` (`traceparent`, `tracestate`, `baggage`), alinhado à spec MCP 2026-07-28 |

> **Maturidade (consultado em 25/10/2026).** Tudo sob `gen_ai.*` está em status **Development**: não é estável. Em junho de 2026 (release v1.42.0 das semantic conventions) as convenções GenAI saíram do repositório principal e passaram a viver em `open-telemetry/semantic-conventions-genai`, ainda sem release versionado; as páginas antigas em `opentelemetry.io` são avisos de "moved". Antes disso, a release v1.37.0 (agosto de 2025) renomeou `gen_ai.system` para `gen_ai.provider.name` e depreciou os eventos por mensagem. Na prática coexistem três gerações de atributos emitidas por frameworks diferentes, além de vocabulários paralelos. Recomendação: adote `gen_ai.*` como **padrão emergente**, mas mantenha uma **camada de normalização própria** (os campos do livro servem como esquema interno) entre os instrumentadores e o backend, e fixe a versão da convenção que cada instrumentador emite.

## 📊 Campos mínimos sugeridos

```text
trace.id, span.id, parent.id,
agent.name, agent.version,
model.name, model.version, prompt.version,
tenant.id (hash), user.id (hash),
input.tokens, output.tokens, cached.tokens,
cost.usd, latency.ms, ttft.ms,
retriever.index, retriever.dimensions, retriever.scores,
tool.name, tool.version,
policy.bundle, policy.decision, policy.reason,
guardrail.triggered, guardrail.action,
error.code, error.kind (if any)
```

## 🧠 Sampling consciente

Tracing 100% em escala é caro. Sampling **mal feito** esconde exatamente o caso interessante. Estratégias úteis:

- **Tiered sampling.** Alto em erros, alto em casos novos, alto em tenants críticos; mais baixo em tráfego rotineiro.
- **Head sampling** (decidido no início) é mais barato; **tail sampling** (decidido depois) captura caudas com mais fidelidade.
- **Forçar 100% em incidentes ativos** com toggle operacional.

## 🧠 Replay de traces

Salvar traces estruturados permite **replay**: re-executar a mesma entrada contra versão candidata e medir diferença. Replay é a forma mais honesta de "test in production" sem afetar usuário real.

Para que replay funcione:

- Inputs precisam estar capturados em forma reproduzível.
- PII precisa estar redigida desde a captura.
- Tools com efeito colateral precisam ter **mock/replay mode**.

## 🚨 Custo de observabilidade

Tracing semântico não é grátis. Custos típicos:

- Volume de span por tarefa: dezenas em agentes complexos.
- Retenção: regulação pode exigir 6–24 meses para audit.
- Backend: armazenamento + indexação + queries.

Decisões de redução de custo passam por: sampling, compactação de payload, retenção em camadas (hot/warm/cold) e separação entre *trace de operação* (curto prazo) e *trace de auditoria* (longo prazo).
