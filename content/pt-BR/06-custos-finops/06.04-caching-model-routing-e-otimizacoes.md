# Capítulo 6.4 — Caching, model routing e otimizações

## 🧠 Técnicas

| Técnica | Benefício | Trade-off |
|---|---|---|
| Prompt caching | Reduz custo e latência de prefixos; leitura de cache ≈0,1× do preço de input nos três grandes provedores (consultado em 25/10/2026) | Exige prefixo estável e mínimo de tokens por modelo (512–4.096); escrita pode custar extra (1,25×/2×) ou armazenamento por hora, conforme o provedor (Cap. 6.1) |
| Semantic cache | Evita recomputar respostas similares | Risco de resposta stale |
| Model routing | Usa modelo menor quando possível | Roteamento pode errar |
| Reranking seletivo | Melhora qualidade onde importa | Custo adicional |
| Streaming | Melhora percepção de latência | Não reduz custo total |
| Batch API | −50% no preço de tokens nos três grandes provedores (consultado em 25/10/2026); pode combinar com prompt caching, confira por provedor | Janela de conclusão de até 24 h; limites de requisições e tamanho por lote; só para carga que tolera espera |
| Compactação de contexto | Reduz tokens | Pode perder evidência |
| Tool result compression | Reduz contexto | Pode esconder detalhes |
| Early exit | Encerra com confiança alta | Pode parar cedo demais |
